## 수정 사항

1. `src/core.mjs`와 `src/view.jsx`를 원본으로 삼고 `build.mjs`가 등록용 JSX를 생성한다. 맵은 `data/world.json`, 이미지 원본은 `assets/npcs/*.svg`. 생성 파일 수동 수정은 `npm test`에서 실패한다.
2. 코어와 등록본의 실제 상태 전이를 같은 입력으로 비교한다. 테스트가 다른 구형 엔진을 검증하던 문제를 제거했다.
3. 대사 공개 기록은 컷별 최대 공개 글자 수를 보존한다. 재생 커서를 되돌려도 이전에 본 문장은 유지한다. 최대 16컷 전체를 인계하며, 보지 않은 접미부를 포함하지 않는다.
4. 페이지 구분에 넣던 인공 줄바꿈을 없애 원문·유니코드·경과시간 비율을 일관되게 계산한다. 연속 다음 버튼이 미공개 페이지를 건너뛰지 않도록 갱신을 고쳤다.
5. 40개 이후 과거 reply ID를 버리지 않도록 수정했다. 저장·복원 뒤에도 중복 시간 가산을 방지한다. 기록은 최대 2048개에서 명시적으로 중단하며 오래된 ID를 조용히 잊지 않는다. 장기 세션의 ID 보존 방식은 후속 설계 과제다.
6. 잘못된 복원 데이터를 새 게임으로 조용히 대체하지 않는다. 원본 입력과 오류를 보존하고 진행을 잠근다. 새 props는 새 세션으로 마운트한다.
7. 외부 지도 로딩 중 진행을 잠가 늦은 응답이 플레이 진행을 덮어쓰지 않게 했다. 12초 응답 제한 및 네트워크/JSON 오류 처리를 추가했다. 유효한 체크포인트가 없으면 내장 맵으로 계속할 수 있다.
8. 서버 저장/복원 요청을 직렬화한다. 저장 성공 응답을 확인한 뒤에만 동기화 리비전을 기록한다. 실패 시 로컬 상태가 유지되며 같은 리비전으로 재시도할 수 있다. 늦은 복원 응답은 변경된 진행을 덮어쓰지 못한다.
9. 저장 스키마에서 잘못된 ID·좌표·응답 기록·압축 발견 지도 등을 거부한다. 서버도 전체 상태를 검증하고 동일 리비전의 다른 저장 내용을 충돌로 처리한다.
10. 여러 바퀴 드래그 회전 후 화면과 실제 방향이 어긋나던 문제를 수정했다.
11. 시야 밖 NPC의 실시간 위치가 미니맵에 노출되지 않게 했다. 정적 발견 물체는 기존대로 남는다. 마지막 목격 위치를 별도 기호로 표시하는 기능은 이번 범위 밖이다.
12. 모바일 대사 글꼴 크기·패널 높이를 조정하고 긴 텍스트가 잘리지 않게 했다. 미니맵의 같은 칸 대상 목록을 한 번 구성해 반복 탐색을 줄였다.

## 용량과 최적화

`metrics.json`은 UTF-8 바이트 실측이며 토큰 수가 아니다. 이미지 24개는 서로 다른 파일이므로 중복 이미지 삭제는 하지 않았다. 불필요한 태그 사이 공백만 줄였다. 최종 JSX는 검증·복구 코드 때문에 조금 커졌다. 맵과 이미지가 커질 때의 외부 데이터 경로와 내장 폴백은 모두 유지했다.

이동/관찰 90건 + 획득 1건 표본의 전체 체크포인트는 7,329바이트, AI 인계 상태는 399바이트다. 이것은 **원래 존재하던 인계 압축을 재검증한 값**이며 이번에 새로 94.6% 줄였다는 뜻이 아니다. 복구용 전체 상태와 대사 공개 기록은 임의 생략하지 않았다.

## 남은 판단과 다음 작업

1. **최우선: 별도 UUMMAI 시험 챗봇에서 E2E 1회 검증.** 새 JSX 등록 → 외부 지도 표시 → NPC 자유대화 → 출력 중 끼어들기 → 새 패널 위치/시간/공개 기록 확인 → 저장/복원. fetch/포인터/sendMessage 제약을 실제 호스트에서 확인한다. 불가한 API는 그때 확인된 범위에 한해 폴백을 결정한다.
2. **등록 이름 세대 충돌 해결.** 옛 1~12차 시험을 남길지, 별도 이름으로 유지할지 결정해야 한다. 이름 변경이나 옛 명령 삭제를 이번에 임의 수행하지 않았다.
3. **서버 변경 배포·통합.** 패치를 검토해 작업 브랜치에 통합하고 기존 Worker에서 빌드된 후보를 배포한 뒤 `/health`, `/hub/health`, `/hub/world.json`, KV 저장/복원·충돌을 확인한다. 현 서비스는 이전 서버 검증 규칙을 사용 중이다.
4. **인라인/아웃라인 정합성 엔진.** 사건 발생 전 조건/행위, 발생 순간 고정 진상, 발생 후 공개 증거·NPC 지식을 구분하는 상태 계약을 먼저 작성한다. 사용자 개입으로 사건이 취소/변경되는 테스트를 만든 다음 코딩한다. 승인 없는 본편 사건·범인 설정은 만들지 않는다.
5. **캐릭터 조립 도구.** 기존 레이어·방향 에셋 계약을 먼저 고정하고, 실제 사용할 한 캐릭터/한 자세의 부품으로 호환성을 검증한 뒤 자동화한다. 최종 그림체·부품 범위는 사용자 판단이 필요하다.

기술 한계: KV는 강한 트랜잭션/원자적 compare-and-swap 저장소가 아니다. 이번 충돌 검사는 순차 요청의 구버전 덮어쓰기를 막지만 여러 기기의 동시 저장을 완전히 보장하지 않는다. 실제 동시 다중 클라이언트를 지원할 때 별도 저장 설계가 필요하다. 현재 저장 인증은 복구 키 방식이며 메시지의 출처를 암호학적으로 증명하지 않는다. reply ID가 들어오기 전부터 이미 잊힌 구버전 ID는 이번 패치로 복구할 수 없다.

## 재현과 수정 위치

Node 22 이상에서 `cd playtest && npm ci && npm run build && npm test && npm run check:jsx`.
브라우저는 `npx playwright install --with-deps chromium && npm run test:browser`.

`node measure.mjs`로 용량 보고서를 갱신한다. 생성 파일을 손으로 편집하지 않는다.
