# 무대·시간·탐색 UI 설계 (2026-11-24 합의, 구현 전)

정본 설정은 `STORY.md`. 이 문서는 그 설정을 화면(JSX)·로어북으로 어떻게 옮길지에 대한 설계다.

## 1. 맵
- 무대: 바다 위 폐업 리조트 호텔. 처음부터 열림, 작중 이유가 있는 곳만 잠금(열쇠·사건으로 열림).
- 화면은 **방 하나 = 한 화면**, 문 칸을 밟으면 짧은 암전 후 전환. 복도도 '방'으로 취급하되 복도처럼 그린다.
- 내부 계산(길찾기·NPC 일정·시야)은 **층 단위 격자 하나**. 그림은 방마다 따로(격자 위에 덧씌움). 통행 불가인데 통행 가능해 보이지 않게 한다(트릭용 예외는 격자로 의도적으로 만든다).
- 문 너머에서 오는 인물은 보이지 않는다(시야 = 같은 방).
- 1회차는 정보가 적어 사건을 막기 어렵게, 넓은 맵에서 NPC가 정해진 일정대로 움직인다 → 대부분 노멀 인라인으로 수렴, 2회차(진엔딩)는 지식으로 흔든다.

## 2. 물건(증거)의 시간 통제
- 물건마다 **등장 조건**을 둔다: 시각(예: 2일 06:00 이후), 플래그·사건(예: 범인 일정 `숨기기`가 끝나면), 또는 둘 다. 조건 전에는 그 서랍·옷장에 없다.
- 물건의 위치는 상태로 움직인다: 처음 위치 → NPC 행동으로 이동·소멸 → 플레이어가 집으면 소지품.
- 조사(서랍·옷장 열기)는 화면이 판정한다. 결과는 증거 카드(언제·어디서·무엇)로 남고, AI에는 코드로만 전달.

## 3. 시간대 표식과 갈래
- 머리말 표식 예: `#장1 #1일저녁A`. 로어북 키워드는 `#` 없이 `1일저녁A`(플랫폼이 `#`을 지운다). A·B·C끼리 서로의 부분 문자열이 되지 않게 이름을 붙인다.
- **A = 인라인(메인)**, B·C… = 가능성이 높은 아웃라인(예: 특정 인물 사망·동행·사건 저지). 어느 갈래인지는 **화면이 조건(플래그·생사·사실)으로 판정**해 표식을 붙인다. 플레이어에게는 알리지 않는다.
- 역할 분담: **이동·행동(어디로, 언제)은 화면 일정표**, **목적·심리·대사 방향은 로어북**. 둘이 어긋나지 않게 '만약 ~하면 ~대신 ~' 규칙은 같은 내용을 일정표 조건과 로어북 문장 양쪽에 둔다.
  - 예정 행동이 의미 없어지는 경우(플레이어가 대신 그곳을 조사함 등)는 일정표에 `건너뛰기 조건`으로 넣고, 로어북에는 그 인물이 그때 할 말·태도를 적는다.
- 장기 과제: 시나리오 원본 한 파일에서 **일정표(JSX)와 로어북 텍스트를 함께 생성**하는 빌드 도구(불일치 방지).

## 4. 시간 건너뛰기(필수)
- 다음 시간대까지 휴식 / 자고 아침으로 / 시각 지정. 건너뛰는 동안 세계는 일정대로 진행된다.
- 플레이어와 관련된 사건(시체 발견 알림, 누가 찾아옴, 공지)이 생기면 그 시점에서 멈춘다.
- 작중 설명: 꿈의 주인 바쿠의 호의(게임적 허용 = 복선).

## 5. 참고 UI 응용(그대로 쓰지 않음)
| 참고 | 우리 쪽 |
|---|---|
| 스킬(마스터키·순간이동·타임리프) | **바쿠의 호의**: 객실로 귀환, 시간 건너뛰기. 능력이 아니라 꿈 주인의 편의 |
| 타임리프 시각 선택 + 그때 각자 하는 일 미리보기 | 시각 선택 + **플레이어가 아는 것만**(공지된 일정, 직접 본·들은 것). 남의 계획은 보이지 않음 |
| 동거 노트(인물 카드, 친해질수록 메모 해금, ???) | **인물 수첩**: 초상·공개 프로필, 대화·조사로 알게 된 사실이 메모로 붙고 모르는 칸은 ??? |
| 오늘 일정(공용 이벤트 + 인물별 루틴) | **공지 일정**(식사·바쿠 공지·재판) + **목격 기록표**: 본 것·들은 것으로 자동 정리되는 인물별 시간표(알리바이 표, 출처 표시: 목격/증언) |
| 추억(물건·장면 갤러리, 처음 본 날·횟수) | **증거 파일**: 물건 카드(처음 발견 시각·장소·설명), 주요 장면 회상 |
| 상단: 장소 + 인물 상태, 다음 이벤트 | 상단: 장소·시각 + **다음 공지**(예: 19:00 연회장 저녁) |
| 왼쪽 세로 메뉴 | 모바일 360폭이라 세로 메뉴 대신 ≡ 메뉴(아이콘 격자)·전체 화면 시트 |
